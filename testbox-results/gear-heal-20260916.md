## Root cause of the 7 stuck online bots (from the code, eb1d68918b tree)

`BotPopulationManager::HealUnrenderableGear` (src/modules/PlayerbotV2/Fleet/BotPopulationManager.cpp:537):
- line 543: `if (p->IsInCombat()) return false;` — bails while the bot is in combat.
- Only call site is the 5-min gear-backfill loop (line 698). **There is no bot-login call site** (grep: HealUnrenderableGear appears only at def:537 and call:698). So the "runs at bot login" behavior is not in this tree — it only runs on the backfill pass.

The 7 stuck bots are all low-level melee levelers, in near-constant combat:
```
Amparo   L14 warrior     Bianarine L21 warrior   Civility L18 DK
Gregg    L21 DK          Kaelario  L23 warrior   Sellarino L16 warrior
Zandrino L24 warrior
```
(all wearing 251573-251580 in slots 0,2,4,5,6,7,8,9)

So: on every backfill pass they are in combat -> `HealUnrenderableGear` returns at line 543 -> never healed. Re-login didn't help because there is no login-time heal. The 226 already-bagged pieces are from bots that happened to be out of combat during some pass (or healed on an earlier binary). Offline bots (142) simply are not iterated.

**Suggested fix direction (yours to decide):** give HealUnrenderableGear a path that survives combat — either retry-until-out-of-combat is too slow for a perpetual-combat leveler, so consider forcing the unequip-to-bags even in combat (removing an unrenderable item to bags is a server-side safety action, not a player convenience gated by combat), and/or call it on the bot-login hook so a fresh (out-of-combat) login heals immediately.
